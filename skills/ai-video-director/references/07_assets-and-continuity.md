# 资产引用、参考职责与连续性

## 一、先核对资产，再写提示词

优先核对当前项目的正式视觉资产索引，并在需要时检查原始文件。真实文件名用于幕后核验；视频提示词使用稳定语义别名。

必须区分：
- 文件存在；
- 已实际打开并看过图片；
- 已上传到视频生成平台；
- 已在工作流或节点中绑定；
- 模型实际使用并生成出符合预期的结果。

这些是不同证据层级。不能把索引文件名当作已上传资源，也不能声称已经参考了没有实际看过的图片。

素材被替换或更新时，必须重新核对当前来源中的文件标识及版本状态，不沿用失效的引用。

## 二、参考资产职责

| 类型 | 主要用途 | 必须说明 |
|---|---|---|
| 人物图 | 身份、面容、发型、体态、服装 | 哪些身份特征需要保持 |
| 载具/机械图 | 外形、结构、比例、部件连接 | 哪些结构、状态和功能已确认 |
| 场景图 | 地形、空间、道路、出入口、材质 | 是空间布局参考还是综合色/材质参考 |
| 道具图 | 尺寸、材质、结构、颜色、开合和磨损 | 哪些识别特征不能改变 |
| 生物图 | 数量、身体结构、变体、行为能力 | 个体差异和已确认能力 |
| 音频 | 声线、口音、语速、语气或环境声 | 继承声音质感，不自动照搬样本台词 |
| 视频 | 运镜、动作、节奏或连续性 | 明确只借鉴哪一部分，不默认复制构图、角色或场景 |

角色、载具和关键道具通常需要实际原图作为身份锚点；环境图优先提炼地形、材质、色彩和光照为文字，避免把原图构图强加给新机位。只有精确空间布局确实重要时，才把环境图作为空间参考。

## 三、类型化资产标签

标签格式固定：

~~~text
<Picture 资产名称>：用途与参考内容描述
<Audio 资产名称>：用途与参考内容描述
<Video 资产名称>：用途与参考内容描述
~~~

规则：

1. 类型固定使用 Picture、Audio、Video，大小写一致。
2. 名称使用简短、稳定、可读的语义别名，不写文件名、扩展名、路径、平台编号或纯数字。
3. 别名作用域是整份 MD 文档，不是单个批次。
4. 同一实际资产跨批次必须使用完全相同的媒体类型和别名；不同实际资产不得共用别名。
5. 同一主体的不同素材若作用不同，应使用彼此可区分的稳定别名。
6. 每个标签独占一行，从行首开始，使用中文冒号，后面简洁说明用途。
7. 只列本批真正使用的资产，不为完整感堆入无关素材。
8. 标签是制作侧引用，不代表已上传、已绑定或模型已成功读取。

TerryDirector 节点按“媒体类型 + 别名”跨批次匹配和同步绑定。用途说明可以因批次不同而变化，匹配键不变。

## 四、文档级待生成图片 Prompt

所有缺失图片的完整提示词集中在整份 Markdown 开头唯一的 [待生成资产] 区域。没有缺失图片时省略该区域。

~~~text
[待生成资产]
<Prompt 资产名称>：完整中文自然语言生图提示词
~~~

强制规则：

- 整份 MD 最多一个 [待生成资产] 区域，位于第一批之前。
- 每张待生成图片只定义一次 Prompt。
- 每个 Prompt 名称必须与后续实际使用它的 Picture 名称完全相同。
- 每个批次只写同名 Picture 引用，不重复 Prompt，不写“同上”替代引用。
- 节点先提取文档级 Prompt，再关联批次 Picture，并从视频模型正文剥离。
- 每个 Prompt 至少被一个批次的同名 Picture 引用；没有被引用的 Prompt 是孤立定义。
- 图片生成并导入后，只删除开头对应的 Prompt 定义，保留所有批次的 Picture 并绑定实际图片。
- 正式资产已存在、只是尚未上传平台时，只写对应媒体标签并注明“待上传绑定”，不要新增 Prompt。
- 当前规则只扩展到图片 Prompt，不自行创建音频或视频生成任务。

标签不得使用 XML 闭合标签、嵌套或属性。不要把 H3 官方数字编号当成语义别名。

## 五、核心电影静帧、首帧和参考图的区别

- 核心电影静帧：统一整场戏的空间、光线、综合色、材质和人物/环境关系。
- 视频首帧：锁定当前视频在0秒时的真实画面状态。
- 中间关键帧：锚定动作过程中的特定状态。
- 尾帧：真实生成并实际提取的上一镜结束画面。
- 身份参考：约束人物或物体外形，不自动锁定姿势和构图。
- 空间参考：约束地形、建筑、道路和空间关系，不自动成为首帧。
- 运镜参考视频：只继承明确指定的摄影机路径或节奏。

上一镜尚未生成时，不创建虚假的尾帧引用。真实尾帧用 Picture；直接引用源视频用 Video。新机位可以把上一镜作为身份、伤痕、道具、光线和方位参考，但不能机械复制旧机位构图。

## 六、连续性状态账本

只追踪会影响当前镜头或后续镜头的状态：

- 人物位置、朝向、衣物、伤痕和知识状态；
- 道具 ID、数量、持有人、开合和损坏状态；
- 载具位置、方向、运行和机械损伤；
- 生物数量、分布和行为状态；
- 空间位置、出入画方向和行动轴线；
- 灯光方向、天气、时间和环境变化；
- 尚未结束的动作及其起始阶段。

复杂任务可在内部使用：

| 镜号 | 事件前 | 主要可见动作 | 事件后 | 摄影机/轴线 | 依赖与风险 |
|---|---|---|---|---|---|

正典事实、工作推测和未知事实必须区分。计划状态不是实际验证状态。

## 七、资产缺口与补图

只有镜头真正需要视觉锁定、又找不到合适正式资产时才补图。不要为每块碎石或普通背景自动创建资产。

缺图提示词应说明资产用途、主体与环境关系、需要的视图、尺度、结构、材质、光线及正典边界。角色、载具、关键道具和生物优先考虑可复用设定图；未建档的复杂场景可建立空间资产图；需要精确机位时另做视频首帧图。

实际生成或修改图片时，遵循当前项目指定的生图流程，读取正式原图并真实调用图像生成工具。只提供提示词时，不声称图片已经生成。

## 八、H3 的数字编号

制作侧的语义标签与 H3 官方数字标签分开：
- 制作侧：Picture、Audio、Video 类型加文档级稳定语义别名；
- H3 正式输入：Picture 1、Audio 1、Video 1 等。

只有真实素材完成映射后，才能按当前批次实际输入顺序分配 H3 数字编号。中文命名标签和 Prompt 不得放进 H3 官方字段。
