# 输出格式、模型正文边界与制作级深度

## 一、先区分两种制作路线

### A. 导演提供分镜或画面方向：协作转译

输入可以是完整分镜，也可以只是部分镜头、关键画面、动作节点、参考图、口头描述或对已有提示词的反馈。默认 Seedance 2.5 参考生图。AI应以这些内容为导演方向，主动补足必要的镜头设计与制作细节，不要求用户先交齐全部逐镜分镜。

每场戏默认先交一次 [核心电影静帧]，已有并确认的母图直接复用，再交视频批次。独立视频提示词块以 [全局资产] 开头，随后只写本批需要的导演说明、连续性、视觉与光影、分镜和声音信息。

推荐顺序：

1. [全局资产]
2. [导演说明]
3. [连续性状态]（有需要才写）
4. [视觉与光影]
5. [分镜脚本]
6. [声音]（有需要才单列；每镜声音也可直接写在镜头字段中）

导演明确指定的镜号、机位、景别、时间、事件顺序、对白、剪点和动作必须保留。未明确指定的部分由 AI 主动补全，包括必要的镜头衔接、机位运镜、动作时间轴、表演、空间、光影和声音。若补充内容会改变剧情因果、人物选择或正典事实，应明确标为提案；用户明确要求忠实转译或禁止新增时，不扩写。

### B. 导演明确授权从剧本直出视频制作稿

只有用户明确要求从现行剧本直接写视频提示词时启用。产物是 AI 拟议制作镜头，不是正式导演分镜，不写入创作/分镜，不反向确认导演意图。

W 式六栏目顺序必须是：

[导演说明] → [全局参考] → [连续性状态] → [视觉基调] → [色彩光影] → [分镜脚本]

每批从 [导演说明] 开始。缺失图片 Prompt 仍在整份 MD 开头唯一的 [待生成资产] 区域；[全局参考] 只写同名 Picture。不得将 Prompt 放进批次正文。

## 二、六栏目实际职责

### [导演说明]

一个完整段落说明本批独有的戏剧任务、观看过程、情绪节奏和镜头之间的关系。观众首先注意什么，依次发现什么，人物如何通过动作体现心理，本批如何承接上一批、留下什么状态。

不是一句主题口号，不重复整集总意图，也不复述剧情摘要。

### [全局参考]

只列本批真正使用的资产及其职责。角色、载具、场景、道具、生物、音频和视频参考都必须说明约束范围。语义别名跨批次稳定。无关资产不堆入。

### [连续性状态]

不是整集设定摘要。明确本批开始状态、发生的关键变化和结束状态：人物位置/朝向、道具持有人、设备状态、载具损伤、光线和未结束动作。不能用“同上”“状态不变”代替必要事实。

### [视觉基调]

写具体摄影机立场、真实机位、景别分工、运镜路径、表演、材质与物理反馈。不要只写焦段清单、摄影机品牌或“电影感、写实、手持”。

### [色彩光影]

写实际光源、方向、范围、强弱、场景综合色、阴影色和材质受光。不能只写“冷色调”“暗部丰富”。

### [分镜脚本]

每个镜头有独立观看目标，按时间顺序写：
- 镜头编号与时码；
- 景别 / 焦段；
- 运镜 / 视角；
- 画面描述；
- 声音 / Foley。

画面描述按起始构图与状态 → 人物/物体动作 → 接触、受力或环境反馈 → 结束构图与状态展开。对白保留原文，明确说话者、说话时动作、语言和听者反应。

## 三、制作级内容深度

批次必须是可独立执行的模型输入，不是剧情摘要、拍摄提纲或导演备忘录。

详细度由戏剧复杂度、生成难度和观众必须读懂的信息量决定：
- 简单固定远景可以简洁，但仍要交代机位、构图、主体运动、环境状态和声音；
- 物件发现、表演转折、机械动作、群像行动、追逐、跳跃、空间转换和关键道具揭示必须展开到可执行程度；
- 不设机械字数、镜头数或每镜秒数配额；
- 不把导演说明缩成口号，不把视觉基调缩成焦段清单，不把光色缩成冷暖形容词，不把连续性缩成“承接上批”；
- 六栏目之间分工互补，不逐栏复制同一句话；
- 不为增加字数添加无意义设备操作、重复确认、空镜或微表情；
- 不得擅自补造关键人物、道具、灯光来源、声音事件或剧情因果。
- 在内部先标出本批主事件、辅助动作、真正值得看清的变化和计划完成点；在 [导演说明] / [视觉基调] / [分镜脚本] 中只体现与当前生成有关的重点，不额外增加供模型读取的“主次分析表”或管理栏目。
- 具体动作只补足当前观看目标真正需要的受力与结果；跳跃前的压缩属于可简短呈现的局部细节，不因存在跳跃而增加专门镜头或时长，也不牺牲仍在发生的追逐与人物关系。强烈情绪爆发仅按剧情要求处理，不套用动作蓄力。
- [分镜脚本] 每镜应明确它给观众带来的独有信息或感受，机位／景别要足以看清所宣称的关键动作；场景中尚在持续行动的其他主体，需通过同框、视线、运动或声音等适当线索保持连续，不因资产已列在参考中就视为已经拍到。
- 关键动作的起势、发生和结果优先在自然边界内兑现；跨批时写明具体交接状态，保留导演明确剪点，不强行把所有阶段挤进一个批次。

## 四、模型正文必须干净

模型正文只保留当前生成任务真正需要的信息。

以下内容放在正文之外：
- 批次名称、建议时长、镜号范围；
- 版本日期、修改原因和制作定位；
- 全集总时长、批次数量和统一设备清单；
- 整季人物百科、世界观摘要和无关设定；
- Skill介绍、工具说明、对模型的解释；
- 与当前画面无关的规则和制作备注。

W 式视频模型正文从 [导演说明] 开始。导演逐镜转译的 Seedance 正文从 [全局资产] 开始。H3 正式提示词另起独立代码块，官方指令与字段结构不得混入自定义栏目。

## 五、镜头和批次独立性

每批必须独立理解，不依赖模型记住上一批、上一轮聊天或另一份文件。需要继承的状态必须在本批写明。镜头可以在批次内硬切，但切点必须有明确时间和观看目的。

不保证模型逐帧精确执行剪点。剪点是制作目标，实际素材仍需审片和后期剪辑。

## 六、单镜简版

简单单镜可以只写：资产职责 → 摄影机位置与状态 → 主体动作 → 结束状态 → 现场声。不强制填空栏目，也不强制每镜都输出一段长导演说明。

## 七、自动格式校验

交付 Markdown 后可运行：

~~~bash
python scripts/check_video_batches.py
python scripts/check_video_batches.py "创作/视频提示词/具体文件.md"
python scripts/check_video_batches.py --format html --output video-batch-report.html
python scripts/check_video_batches.py --format json --output video-batch-report.json
python scripts/check_video_batches.py --fail-on-warn
~~~

校验器检查资产标签、文档级 Prompt、批次栏目、镜头时码、字段完整性和 H3 官方字段结构。它不判断戏剧质量、摄影风格、物理正确性或生成画面是否成功。格式 PASS 不等于导演验收通过。
