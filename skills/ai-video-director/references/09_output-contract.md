# 输出格式、模型正文边界与制作级深度

## 一、文件命名约定

视频分镜／生成提示词文档的文件名以作品内容和交付物类型命名，不绑定某个模型或模型版本。

- 文件名不包含“Seedance 2.0”“Seedance 2.5”“MiniMax H3”等模型名称或版本号。
- 统一以“_分镜提示词”作为文件名后缀。
- 推荐格式：`{集数}_{集名}_分镜提示词.md`，例如 `01_异星拾荒_分镜提示词.md`。
- 模型与版本信息如有记录需要，写在文档正文的制作说明中，不放进文件名。

## 二、《异星边境》批次约束

以下规则覆盖 W 分镜脚本大师中的通用批次默认值：

### 批次时长

- 每批为 **5–15 秒**。
- 15 秒是上限，不是默认目标；不为了凑满时长添加无意义动作。
- 先按戏剧 Beat、自然剪点、完整动作、对白和观看节奏规划，再确定批次时长。
- 不按全片时间轴机械地每 15 秒截断；导演明确要求连续的一镜到底不得从中间硬切。
- 批次标题中的时长必须与本批最后一个镜头的结束时码一致。

### 批次标题

统一使用：`批次N_批次主题_(N秒)`。

- 第一个 N 是连续递增的批次编号，不补零。
- “批次主题”概括本批真正的观看内容与核心事件，不写成“建议15秒”等时长说明。
- 括号内填写本批实际时长。

### 批次内镜头编号与时间码

- **每个批次内部独立编号。** 每批第一镜必须从“镜头01”开始，随后为“镜头02、镜头03……”连续递增；进入下一批后重新从“镜头01”开始，不跨批累计。
- 每批内部时码从 0 秒重新计算，并连续覆盖该批实际时长。
- 镜头编号和时间码是两个独立维度：镜头编号按批次重置，批次编号在整份文档中连续递增。

### 每批环境图片

- **每个批次至少引用一张与本批场景相关的环境图片。**
- 环境图片用于约束场景空间、地貌、建筑、地形结构、环境质感或空间纵深；不能用人物图、载具图、生物图或道具图代替环境图片。
- 每批在 `[全局参考]` 中明确写出环境图片的稳定 Picture 语义别名及其约束内容。
- 如果现有资产库缺少合适环境图，在整份 Markdown 开头的唯一 `[待生成资产]` 区域定义环境图 Prompt，并在对应批次引用其 Picture 别名；不得只写一段环境文字就视为完成环境图片引用。
- 同一环境资产跨批次使用时，Picture 语义别名必须保持一致。

## 三、Seedance 批次的 W 六栏目结构

**所有 Seedance 分镜提示词批次统一使用 W 分镜脚本大师的六栏目结构**，无论用户提供了完整分镜、局部镜头方向，还是要求从剧本直出。不得因输入形式不同，擅自改用另一套简化栏目。

栏目顺序固定为：

`[导演说明] → [全局参考] → [连续性状态] → [视觉基调] → [色彩光影] → [分镜脚本]`

每个批次正文从 `[导演说明]` 开始。整份 Markdown 中缺失图片的 Prompt 集中放在文档开头唯一的 `[待生成资产]` 区域；批次的 `[全局参考]` 只引用同名 Picture，不重复粘贴 Prompt。

### [导演说明]

用完整段落说明本批次的核心戏剧意图与观众体验：

- 观众首先注意什么，随后发现什么；
- 信息以什么顺序、速度和完整程度传递；
- 镜头之间如何形成节奏、视角和观看关系的变化；
- 人物经历什么，场面关系如何推进；
- 本批如何承接上一批，并为下一批留下什么。

导演说明不是一句主题口号，也不是剧情摘要。不要把抽象的“信息差”“紧张感”“电影感”直接当成模型指令；要说明它们将如何由本批的镜头顺序与视听安排实现。

### [全局参考]

只列本批真正使用的参考资产，并说明每张图的具体约束职责：

- 人物：外貌、发型、服装、体态；
- 载具／机械：外形、结构、材质、部件状态；
- 生物：种类、外形、身体结构与变体差异；
- 道具：形状、材质、状态与使用方式；
- 环境：空间结构、地貌、建筑、场景纵深、综合色与环境材质；
- Audio / Video：明确声音、表演、运镜或节奏参考的具体用途。

每批至少有一张环境图片。资产语义别名在整份文档中保持稳定；无关资产不堆入。资产标签本身不代表主体已经进入镜头，具体出场、位置与动作仍须在分镜正文中写清。

### [连续性状态]

明确本批开始时的状态，以及本批结束后需要继承的状态：

- 人物位置、朝向、动作、服装与伤势；
- 道具持有人、设备开关与损坏状态；
- 载具位置、运动方向与损伤；
- 其他人物、生物和环境主体的相对位置；
- 光线、天气、时间和环境变化；
- 本批结束时尚未完成的动作。

连续性状态不是整集设定摘要。不能用“同上”“状态不变”代替本批生成所需的具体状态。独立且不存在跨镜连续性要求的单镜任务，可按需省略。

### [视觉基调]

**只负责约束画面质感与整体摄影风格。** 可包括：

- 真人实景、写实程度与整体影像气质；
- 摄影机型号、电影镜头系列及适合的焦段范围；
- 画幅、画面比例、景深和成像特征；
- 皮肤、织物、金属、岩石等材质的影像质感；
- 胶片颗粒、锐度、Bloom、Halation 等成像质感；
- 整体摄影风格，例如真实手持呼吸感、流体 FPV、稳定器运动或冷静固定大远景。

摄影器材和镜头型号应服务于画面目标，不为显示专业而堆砌参数。整体摄影风格只描述本批的成像和拍摄质感；具体镜头的机位、景别、运动路径、人物表演和动作安排写在 `[分镜脚本]`，不在本栏重复。

本栏不写剧情解释、观众信息顺序、人物心理、具体场面调度、逐镜运镜路线、动作过程、声音设计或色彩光线方案。

### [色彩光影]

**只负责约束画面的色彩、光线与氛围。** 可包括：

- 时间与环境光条件；
- 主光、辅光、Negative Fill、环境反射光和实用光源；
- 光源方向、范围、强弱、色温和衰减；
- 场景综合色、冷暖关系、饱和度与对比度；
- 阴影层次、高光控制、体积光和空气透视；
- 不同材质在当前光线下的反射、漫反射与透光表现。

本栏描述画面呈现出来的光色状态，不写剧情解释、人物表演、摄影机运动、动作调度、声音或其他制作事项。若镜头中确实发生可见的光线变化，只描述其实际光色和明暗变化；镜头如何拍摄该变化写在 `[分镜脚本]`。

### [分镜脚本]

每个镜头必须写镜头编号与时间段，并根据实际需要组织以下内容：

- 景别 / 焦段；
- 运镜 / 视角；
- 画面描述；
- 声音 / Foley。

画面描述应像真正的影视分镜一样连贯、具体、可执行。根据镜头需要交代起始构图、人物与物体的位置、主体动作、表演和视线、空间关系、动作物理过程、环境反馈、摄影师反应、焦点变化、前景遮挡，以及结束构图和状态。

动作按可见过程展开，不只写结果词。重要动作应让观众看清必要的触发、发生、接触／受力、反馈和结果；简单动作不需要冗长拆解。人物表演通过可观察的动作、目光、姿态、呼吸和反应呈现，不只写情绪形容词。

运镜要写清实际视角与摄影机行为。需要时交代起点、路径、速度、相对主体的变化和终点构图；固定镜头也可以成立，不为了“电影感”强行增加运动。摄影机必须符合真实空间可达性，不能穿过实体或无故瞬移。

声音与画面动作对应，写出环境声、Room Tone、Foley、机械声、脚步、衣料、呼吸、对白等。默认无画外配乐；有剧情来源的现场音乐按实际声源处理。

## 四、内容深度与写作质量

批次必须是可独立执行的模型输入，不是剧情摘要、拍摄提纲或导演备忘录。

- 以用户提供的原版 `00_w-storyboard-master.md` 为写作核心，保持完整、连贯、专业的影视分镜表达。
- 不把导演说明缩成口号，不把视觉基调缩成焦段清单，不把色彩光影缩成冷暖形容词，不把连续性缩成“承接上批”。
- 不把分镜写成几句简短的剧情复述，再机械附上“景别 / 运镜 / 画面描述 / 声音”标签。
- 简单固定远景可以简洁，但仍要交代机位、构图、主体运动、环境状态和声音。
- 人物表演转折、物件发现、机械动作、群像行动、追逐、空间转换和关键事件必须展开到可拍摄、可生成的程度。
- 不设机械字数、镜头数或每镜秒数配额；详细程度服从戏剧复杂度、生成难度和观众必须读懂的信息。
- 六栏目之间分工互补，不逐栏复制同一句话；不为增加字数添加无意义操作、重复确认、空镜或无因微表情。
- 不得擅自补造关键人物、道具、能力、灯光来源、声音事件或剧情因果。
- 用户明确给出的镜头、机位、景别、时间、事件顺序、对白、剪点和动作必须保留；未指定的制作细节由 AI 主动补全。会改变剧情因果、人物选择或正典事实的新增内容标注为提案。
- 每镜应有独立观看贡献。若删掉、缩短或合并某镜不会损失信息、情绪、动作因果或审美体验，应重新判断它是否必要。

## 五、模型正文必须干净

模型正文只保留当前生成任务真正需要的信息。

不把以下内容塞进批次正文：

- 版本日期、修改原因和制作定位；
- 全集总时长、批次数量和统一设备清单；
- 整季人物百科、世界观摘要和无关设定；
- Skill 介绍、工具说明、对模型的解释；
- 与当前画面无关的规则和制作备注。

待生成资产 Prompt 放在整份 Markdown 开头唯一的 `[待生成资产]` 区域，不混进批次正文。模型正文从 `[导演说明]` 开始。

## 六、连续性与批次交接

每批必须能独立理解，不依赖模型记住上一批、上一轮聊天或另一份文件。需要继承的状态必须在本批 `[连续性状态]` 中写明。

如果上一批结束时人物已经握住门把手，下一批应从仍握着门把手的状态继续；如果车辆已经转向、设备已经损坏、角色已经受伤，下一批不得无故重置。跨批事件必须明确交接阶段和状态；不强迫把所有动作阶段挤进一个批次，也不把未完成动作伪装成已经完成。

## 七、MiniMax H3 例外

明确指定 MiniMax H3 / H3 时：

- W 分镜脚本大师仍然负责指导戏剧意图、摄影、表演、动作和观看体验；
- 最终提示词必须遵循 H3 专项模块与官方字段结构；
- 不把 Seedance 的 W 六栏目结构强行套进 H3 官方正文；
- H3 正文中的镜头编号同样按每个生成批次独立从 1 开始；
- 项目批次与资产约束仍然有效，除非用户明确另行指定。

## 八、自动格式校验

交付 Markdown 后可运行：

```bash
python scripts/check_video_batches.py
python scripts/check_video_batches.py "创作/视频提示词/具体文件.md"
python scripts/check_video_batches.py --format html --output video-batch-report.html
python scripts/check_video_batches.py --format json --output video-batch-report.json
python scripts/check_video_batches.py --fail-on-warn
```

校验器检查资产标签、文档级 Prompt、批次栏目、镜头时码、字段完整性和 H3 官方字段结构。它不判断戏剧质量、摄影风格、物理正确性或生成画面是否成功。格式 PASS 不等于导演验收通过。
