# director-persona-maintainer｜Terry个人导演人格维护

## 1. 这是什么 Skill

**这是 Terry 本人的个人 Skill，不是面向任意用户的通用导演人格模板。**

它保留并维护 Terry 跨项目可复用的个人部分：
- 长期创作判断与价值取舍；
- 个人审美坐标，以及明确喜欢／不喜欢的电影、剧集、游戏和创作者；
- 观察到的创作习惯、讨论方式与协作边界；
- 经过真实改稿反复验证的创作与迭代方法。

这套个人基线可以服务于 Terry 参与的不同项目，但**不意味着所有项目都要拍成同一种风格**。具体项目的题材、世界规则、角色、剧情、镜头规范、制作流程和专属回归案例，必须放在各自独立的项目适配文件及项目正典中。

本 Skill 不负责代写作品本身，也不赋予 AI 代表 Terry 定稿的权限。

## 2. Terry个人资料入口

按任务读取，不要每次无差别加载全部资料：

- [Terry导演人格](references/Terry导演人格.md)：跨项目的长期判断、人物与叙事取向、对白、视觉、协作方式、创作思考和纠偏方式。写作、审稿或需要模拟 Terry 的取舍时读取。
- [Terry审美坐标与作品偏好](references/Terry审美坐标与作品偏好.md)：Terry 明确喜欢的作品、跨媒介审美维度及可调用的导演／创作者参照。涉及作品偏好、风格匹配、摄影或角色视觉校准时读取。
- [Terry创作与迭代方法论](references/Terry创作与迭代方法论.md)：Terry 在真实创作中形成的场面诊断、方案比较、改稿和验证方法。涉及具体问题诊断、复杂改稿时读取。

这三份是 **Terry个人资料**，不属于任何单一项目。只在对应内容确实有帮助时加载。

## 3. 与项目适配文件的关系

当当前任务属于某个有独立项目适配文件的项目时，**必须同时使用本 Skill 和该项目适配文件**：

- 由当前项目的入口文档、用户指示或仓库约定确定适配文件位置，不猜测路径；
- 适配文件负责指向该项目的叙事约束、视觉参照、项目案例与正典；
- Terry个人基线提供“这个创作者通常如何判断”，项目适配提供“这部作品有什么特殊目标和边界”；
- 其他项目应使用各自的适配文件，不得将某个项目的文件路径写成所有项目的固定入口。

职责不可倒置：
- Terry 的跨项目个人偏好、创作习惯和通用方法 → 本 Skill 及其 references。
- 某个项目的世界、人物、剧情、镜头、制作规则、未定提案和回归案例 → 对应项目适配文件或项目正典。
- 不要把《异星边境》的角色名、集数、剧情、世界设定或项目专属禁令写进 Terry 的个人资料。
- 不要把 Terry 的个人偏好误写成某个项目独有的设定，也不要因为个人偏好而覆盖项目明确目标。

若项目没有适配文件，按 Terry 个人基线工作，并依据用户指示和项目现有资料判断，不得虚构项目规则。

## 4. 什么时候使用

- Terry 要求更新、重构、审计或校准个人导演人格。
- Terry 纠正 AI 的创作判断，希望以后在其他项目中也能更准确地理解。
- Terry 补充喜欢或不喜欢的电影、剧集、游戏、书籍、导演或其他作品。
- Terry 要求总结长期创作偏好、分析过往选择规律，或比较创作方案与个人审美的匹配程度。
- Terry 要求回顾上次更新之后遗漏的反馈，进行跨版本完整复盘。

不适用于单次台词润色、单镜头事实修正、普通剧本代写或与长期判断无关的任务。若反馈不能迁移到其他情境，维护结果可以是 `NOOP`。

## 5. 维护流程

### 1）界定回顾范围并捕获证据

先判断这是针对当前反馈的局部更新，还是从上一次人格版本／提交开始的完整回顾。

完整回顾时检查：
- 上一版 Terry 个人资料及版本历史；
- 上次更新之后可访问的相关对话、创作反馈和明确决定；
- 同期项目文件，以确认哪些建议真正被采用；
- 当前仍有效的个人倾向，以及被新决定修订的旧规则。

Git 提交、AI 提案或文件里出现某项内容，都不自动证明 Terry 明确认可。必须区分作者、提案者、批准状态和时间顺序。

证据等级：
- **A｜明确表达：** Terry 直接说出偏好、原则，或明确批准某项长期判断。
- **B｜稳定归纳：** 多个不同情境中的具体选择支持同一倾向，但 Terry 未必直接将其总结为规则。
- **C｜待验证假说：** AI 对原因、动机、审美规律或未来选择的解释，尚未得到 Terry 反馈。

Terry 沉默、继续讨论或未反对，不等于认可。事后解释不能伪装成事前预测命中。

### 2）判断应该进入个人资料还是项目文件

- 跨项目、跨情境的价值取舍和稳定创作优先级 → Terry导演人格。
- 个人明确作品偏好、跨作品审美维度和创作者参照 → Terry审美坐标。
- 可复用的场面诊断、方案比较、改造和验证方式 → Terry创作与迭代方法论。
- 单一项目的世界观、人物事实、剧情因果、镜头要求、制作参数、项目专属案例 → 项目适配文件或项目正典。
- 尚未确认的创意 → 对应项目的提案／灵感资料，并标明状态。

同一条规则不要在个人资料和项目适配文件中全文复制。若个人原则在项目中有特殊应用，只在项目文件写明应用条件和差异，并链接个人基线。

### 3）归纳为可迁移的问题

把相似反馈归纳为能跨情境使用的判断维度，例如：
- 观众实际获得的体验；
- 人物能动性、关系与情感投入；
- 目标、行动、代价与生活变化；
- 信息可读性、悬念和叙事节奏；
- 世界可信性、物理逻辑与资源约束；
- 视觉表达、空间、动作和摄影机立场；
- Terry 明确偏好与尚未验证的审美假说。

对照旧原则：是否已经覆盖？是否出现反例？最新明确意见是否取代旧判断？只有真正改变未来选择的内容才进入长期个人资料。

### 4）选择维护操作

- `ADD`：新增此前缺失、且能改变未来决策的长期判断。
- `UPDATE`：修订、合并或缩小旧原则的适用范围。
- `DELETE`：移除过时、被证伪或不再适用的原则。
- `NOOP`：已有原则足够、只是单次事实、证据不足，或无需修改。

优先考虑 `UPDATE` 和 `NOOP`。不要为了显示做了工作而增加条目。

### 5）回归检查

- 使用 Terry 个人资料中的跨情境原则，检查更新是否提升了不同项目中的判断能力。
- 若当前项目有适配文件，使用其中的项目案例验证个人原则在该项目中的实际应用；不要把项目答案写回个人基线。
- 检查是否能区分真实创作意图与 AI 自行补写的假设。
- 检查是否保留适用条件、代价与例外，而非把偏好变成绝对禁令。
- 不让旧偏好压过 Terry 最新的明确决定。
- 没有执行的测试不得报告为通过；文本一致性检查不能冒充真正的创作判断回归。

### 6）控制体量

- 优先合并相似原则，压缩重复案例，删除已被吸收的旧表述。
- 个人导演人格保持清晰、可调用；目标约 6,000–10,000 字符，原则上不超过 12,000 字符。超限先去重、合并和压缩，不制造多个平行人格文件。
- 审美资料以跨作品判断维度和少量代表证据为核心，不追求片单数量。
- 方法论保留可复用的解决办法与边界，不收纳项目剧情流水账。
- 项目案例留在项目适配文件及项目资料中。
- Git 保存详细变更历史；正文不按日期无限追加日志。

### 7）写入与报告

只有 Terry 明确要求更新、创建、重构或同步时，才写入个人资料或项目文件。没有写入权限或工具不可用时，交付可应用的修改方案并如实说明。

写入前核对：
- 修改的是正确的个人资料或项目；
- 没有覆盖同期修改；
- 所有链接和入口均指向实际存在的文件；
- 个人基线和项目适配没有重复维护、互相漂移。

完成后简要报告：
- 采用的操作（`ADD / UPDATE / DELETE / NOOP`）及原因；
- 修改的个人资料和／或项目文件；
- 实际执行的检查及未执行项目；
- 尚未确认、需要 Terry 判断的假说。

## 6. 风格参照的使用原则

先确定当前要解决的是摄影空间、动作、表演、人物关系、节奏、世界可信性、幽默还是长线结构，再从 Terry 的审美坐标中选一主一辅的参照。

作品证据不等于作品影评。Terry 明确说喜欢某部作品，只能确认作品偏好；具体喜欢的原因若未说明，应标为待验证假说。相似风格不代表喜欢该创作者的一切，也不能用名家标签代替对具体画面的分析。

不同项目可以采用不同语言。不要因为 Terry 喜欢某种风格，就让每个项目都复制那种风格。

## 7. 成功判据

- Skill 仍然准确保留 Terry 本人的创作判断、审美偏好和工作方式。
- 项目专属事实、规则和案例已经独立，且能通过项目适配文件与本 Skill 配合。
- 新判断能够迁移到不同情境，并提升未来选择的准确度。
- 明确反馈、稳定归纳、AI 假说和项目事实彼此分开。
- Terry 最新决定始终优先，AI 不代替创作者定稿。
- 没有为了增加条目而增加条目；没有执行的操作和测试不冒充完成。
