# Director Persona Maintainer｜通用导演／创作者人格维护技能

## 定位

本技能提供一套可跨项目复用的**创作者判断维护方法**。它帮助 AI 从用户真实表达、选择和纠错中，逐步形成更准确的长期创作判断；避免把一次讨论误写成永久规则，也避免人格文件无限膨胀。

本技能不预设具体项目、作品类型、角色、剧情、仓库结构或审美名单。它不代写剧本、分镜或作品本身，也不赋予 AI 代表创作者定稿的权限。

## 与项目适配文件配合

若当前项目提供独立的「项目适配文件」「创作人格配置」或等效说明，**必须将该文件与本技能配合使用**：

1. 由项目入口、用户指示或仓库文档确定适配文件位置，不猜测路径。
2. 先读取本技能，再读取项目适配文件；按适配文件指引加载该项目的人格正文、审美模型、方法论和必要的回归案例。
3. 本技能负责通用方法；项目适配文件负责项目路径、文件职责、协作边界、证据语境和项目专属回归范围。
4. 项目适配文件不是第二套通用技能，也不应把大量项目正典复制进来。
5. 若没有项目适配文件，仍可按本技能独立工作；先依据用户提供的信息和项目现有结构识别资料，不得虚构不存在的文件或规则。

**隔离原则：** 不要把某个项目的角色名、集数、剧情案例、文件路径、专属禁令或作品名单写入本通用 Skill。新增项目差异应写入该项目的适配文件或项目资料，而不是修改通用方法。

## 适用任务

- 用户要求更新、重构、审计或校准导演／创作者人格。
- 用户反馈某种创作判断不符合其意图，希望以后能更准确地理解。
- 用户补充喜欢或不喜欢的电影、剧集、游戏、书籍、导演或其他作品，希望更新审美模型。
- 用户要求总结长期创作偏好、分析过去的取舍规律，或比较不同创作方案与其偏好的匹配程度。
- 用户要求回顾上次更新之后遗漏的反馈，进行跨版本完整复盘。

不适用于：单次台词润色、单镜头事实修正、一般剧本代写、分镜代写或与长期创作判断无关的任务。若反馈不能迁移到其他情境，维护结果可以是 `NOOP`。

## 核心资料模型

按项目实际结构维护以下资料；不要求每个项目都必须拆成三份文件：

- **人格正文：** 长期价值取舍、创作优先级、观看体验判断、人物与叙事边界。回答「倾向选择什么、为什么」。
- **审美模型／作品证据：** 跨作品的审美维度、创作者明确表达的作品偏好，以及支持或反驳这些判断的证据。避免膨胀成逐作品影评库。
- **创作方法论：** 具体问题的诊断、方案比较、改造步骤、验证方法与适用边界。回答「遇到问题时怎样处理」。
- **项目正典与制作资料：** 人物、世界、事件、镜头、资产和制作参数等事实，应保留在项目自己的权威资料中，不得为了方便而复制进人格正文。

各资料必须有清晰职责和唯一权威入口。若项目将多种内容合并在一个文件中，也要在文件内部明确区分，避免重复维护。

## 更新流程

### 1. 界定回顾范围并捕获证据

先确定这是针对当前反馈的局部更新，还是从上一次人格版本／提交开始的完整回顾。

完整回顾时，应检查：
- 上一版人格正文及版本历史；
- 上次更新之后可访问的相关对话、创作反馈和明确决定；
- 同期修改的项目文件，以确认哪些建议真正被采用；
- 当前仍有效的约束，以及已被新决定取代的旧规则。

Git 提交、AI 提案或文件里出现某项内容，都不自动证明用户明确认可。必须区分作者、提案者、批准状态和时间顺序。

证据等级：
- **A｜明确表达：** 用户直接说出偏好、原则，或明确批准某项长期判断。
- **B｜稳定归纳：** 多个不同情境中的具体选择支持同一倾向，但用户未必直接将其总结为规则。
- **C｜待验证假说：** AI 对原因、动机、审美规律或未来选择的解释，尚未得到用户反馈。

用户沉默、继续讨论或未反对，不等于认可。事后解释不能伪装成事前预测命中。

### 2. 判断信息应该进入哪份资料

- 跨情境的价值取舍与稳定创作优先级 → 人格正文。
- 跨作品的审美维度、明确作品偏好及其证据 → 审美模型。
- 可复用的诊断、改造、方案比较与验证方法 → 创作方法论。
- 单次镜头、角色事实、剧情因果、场景顺序、制作参数 → 项目正典或制作文件。
- 尚未确认的创意 → 提案／灵感资料，并清楚标注状态。

同一条原则不要在多份文件中各写一遍。若一条规则同时涉及价值判断和执行方法，拆清职责并互相引用，而不是复制全文。

### 3. 汇总为可迁移的问题

把相似反馈归纳为能跨场景使用的判断维度，例如：
- 观众实际获得的体验；
- 人物能动性、关系与情感投入；
- 目标、行动、代价与生活变化；
- 信息可读性、悬念和叙事节奏；
- 世界可信性、物理逻辑与资源约束；
- 视觉表达、空间、动作和摄影机立场；
- 创作者明确偏好与尚未验证的审美假说。

对照旧原则：是否已经覆盖？是否出现反例？最新明确意见是否取代旧判断？只有真正改变未来选择的内容才进入长期人格。

### 4. 选择维护操作

- `ADD`：新增了此前缺失、且能改变未来决策的长期判断。
- `UPDATE`：修订、合并或缩小旧原则的适用范围。
- `DELETE`：移除过时、被证伪或不再适用的原则。
- `NOOP`：已有原则足够、只是单次事实、证据不足，或无需修改。

优先考虑 `UPDATE` 和 `NOOP`。不要为了显示做了工作而增加条目。

### 5. 回归检查

使用项目适配文件提供的代表性案例，检查更新后的判断是否：
- 能处理不同尺度的问题，而非只记住某一场戏或某个镜头；
- 能区分真实创作意图与 AI 自行补写的假设；
- 能解释适用条件、代价与例外，而非变成绝对禁令；
- 不会让旧偏好压过用户最新的明确决定；
- 不会把项目事实、未确认提案和审美推测混为一谈。

如果项目没有适配文件，应从真实历史反馈中选择少量不同类型的案例；不要编造“已测试”的历史结果。区分文本一致性检查与真正的创作判断回归，未执行的测试不得报告为通过。

### 6. 控制体量并保持可维护

- 优先合并相似原则，压缩重复案例，删除已被吸收的旧表述。
- 人格正文应以清晰、可调用为目标；体量上限和版本格式遵循项目适配文件。项目未设限制时，不设僵硬字符指标。
- 审美模型维护跨作品判断维度和少量代表证据，不追求作品清单数量。
- 方法论保留可复用的解决办法与边界，不收纳剧情流水账。
- Git 或项目版本系统保存详细变更历史；正文不按日期无限追加日志。

### 7. 写入与报告

只有用户明确要求更新、创建、重构或同步时，才写入项目文件；没有写入权限或工具不可用时，交付可应用的修改方案并如实说明。

写入前核对：
- 修改的是正确项目与分支；
- 没有覆盖用户同期修改；
- 所有链接和入口均指向实际存在的文件；
- 唯一权威入口没有被复制成多个互相漂移的版本。

完成后简要报告：
- 采用的操作（`ADD / UPDATE / DELETE / NOOP`）及原因；
- 修改的文件与版本；
- 实际执行的检查及未执行项目；
- 尚未确认、需要用户判断的假说。

## 审美参照与风格匹配

当用户要求比较导演、创作者、作品或风格时，先确定真正要解决的问题，再寻找一主一辅的参照。可以分别讨论视觉空间、摄影机运动、表演、人物关系、节奏、世界可信性、幽默和长线结构，不假设某位创作者的全部作品都符合用户偏好。

**作品证据不等于作品影评。** 用户明确说喜欢某部作品，只能确认作品偏好；具体喜欢的原因若未说明，应标为待验证假说。相似风格不代表用户喜欢该创作者的一切，也不能用名家标签代替对具体画面的分析。

## 维护成功的判据

- 新判断能够迁移到不同场景，并提升未来选择的准确度。
- 明确反馈、行为归纳、AI 假说和项目事实彼此分开。
- 用户最新决定始终优先，AI 不代替创作者定稿。
- 人格、审美、方法论和项目正典各有唯一权威入口。
- 没有为了增加条目而增加条目；没有执行的操作和测试不冒充完成。
