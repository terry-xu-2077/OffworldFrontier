# 视频批次自动校验｜使用与规则边界

## 目的

check_video_batches.py 是制作文件的确定性检查工具。它读取现有 Markdown，不要求将剧本、导演分镜或视频提示词迁移成 JSON，也不会改写原文件。

它负责发现**可以明确判断的制作错误**；不评价一场戏是否好看，不判断某种运镜是否正确，也不替导演决定镜头。

## 运行方式

在仓库根目录执行：

~~~bash
# 扫描创作/视频提示词/ 下的全部 Markdown
python scripts/check_video_batches.py

# 只检查指定文件
python scripts/check_video_batches.py "创作/视频提示词/第一季/01_异星拾荒_Seedance2.5.md"

# 输出可浏览的 HTML 报告
python scripts/check_video_batches.py --format html --output video-batch-report.html

# 输出 JSON，供其他工具读取
python scripts/check_video_batches.py --format json --output video-batch-report.json

# CI 严格模式：警告也使进程返回失败
python scripts/check_video_batches.py --fail-on-warn
~~~

默认只扫描 创作/视频提示词/。也可以传入多个 Markdown 文件或目录。

退出码：
- 0：没有错误；普通模式下允许存在警告。
- 1：发现错误；使用 --fail-on-warn 时，存在警告也返回 1。
- 2：路径不存在、没有可检查文件或命令参数错误。

## 检查范围

### 1. 文档级资产区

- [待生成资产] 最多出现一次，且必须位于第一批之前。
- <Prompt 名称> 必须使用独占行和中文冒号，别名不得为空或纯数字。
- Prompt 必须有正文，不得重复定义。
- 每个 Prompt 必须至少被一个批次的同名 <Picture 名称> 引用。
- 批次的 [全局参考] / [全局资产] 内不得出现 <Prompt>。
- 不把代码围栏中的示例当成真实资产定义。

注意：没有 Prompt 的 <Picture> 不会自动报错，因为它可能指向资产库中已经存在的正式图片。仅凭 Markdown 无法判断它是否已上传、绑定或实际被模型读取。

### 2. 类型化资产引用

在 [全局参考] 或 [全局资产] 中检查：

- 标签是否为 <Picture 名称>、<Audio 名称>、<Video 名称>。
- 标签是否独占一行、使用中文冒号并带有用途描述。
- 是否误将纯数字、文件名或路径当作语义别名。
- 同一批次是否重复声明同一类型和别名。

同一别名在不同批次重复出现是正常的；用途描述可以因批次不同而变化。校验器不会仅凭描述文字推断两张图片是否其实为同一资产，也不会擅自合并相似名称。

### 3. W 式 Seedance 批次

识别 W 式六栏目批次，并检查栏目是否齐全、顺序是否正确：

[导演说明] → [全局参考] → [连续性状态] → [视觉基调] → [色彩光影] → [分镜脚本]

对 [分镜脚本] 中每个镜头检查：

- 镜头编号与起止秒数是否可识别。
- 批次时码是否从 0 秒开始。
- 相邻镜头是否连续，是否出现空档或重叠。
- 每镜是否包含景别 / 焦段、运镜 / 视角、画面描述、声音 / Foley。
- 标题及字段行是否保留 Markdown 硬换行所需的两个尾随空格（警告）。
- 标题建议时长与最后一镜结束时码是否一致。

如果批次标题没有写明建议时长，工具不会猜测。**15 秒是当前常用的批次规划标准，不是校验器强制的镜头长度；合理的短批次、长镜头或例外时长均可保留，只需让标题和实际时码一致。**

### 4. MiniMax H3 官方提示词

识别代码围栏中的 H3 官方提示词，并检查：

- 基础模式字段：integrated_multimodal_description、overall_soundscape、non_diegetic_music。
- Ref2VA 模式字段：subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music。
- 字段是否缺失、重复或顺序错误。
- [Shot 1] 是否存在，镜号是否连续。
- 第一镜是否误加切点时码，后续镜头是否有 At MM:SS.mmm 且严格递增。

校验器不会替代 MiniMax 官方规范核对，不会推断当前 ComfyUI 工作流实际接入了哪种模式，也不会把制作侧 <Picture 名称> 自动转换成 H3 官方数字编号。

## 错误、警告与不检查的事项

- **错误**：明确违反文档结构、标签、时码或字段要求。
- **警告**：需要人工确认的排版或编号问题，例如 Markdown 硬换行缺失、批次编号跳号、同批次重复资产声明。
- **不检查**：剧情是否完整、人物表演是否成立、空间调度是否合理、摄影是否有观看价值、资产图是否真的符合正典、视频是否生成成功。

这些内容需要导演审读、资产核验或实际审片。检查通过只代表文件结构符合已编码规则，不代表创作质量或生成结果已经验收。

## 当前支持范围

- W 式六栏目 Seedance 批次。
- 原有 [全局资产] + [分镜脚本] 逐镜转译格式。
- MiniMax H3 基础三字段与 Ref2VA 六字段代码块。
- 文档级 Prompt 与批次 Picture 的引用关系。

遇到未覆盖的旧格式时，工具应给出可定位的提示，不应通过猜测自动修改文件。扩展规则前先用现有真实文件和独立测试夹具验证，避免把某一集的特殊制作选择升级成全项目硬规则。
