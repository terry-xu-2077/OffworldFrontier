# 《异星边境》｜默认生图 Skill

> **无条件默认入口**：在本项目里，用户只要说「生图」「画一张」「生成电影静帧」「做概念图」「修改这张图」或给出明确的新图像／改图任务，就应用本 Skill。用户无须再次说「去云盘找图」「把资产图传给生图模型」「反推文字」「锁定人物和载具」。
> **先做后答**：有图像生成工具时，完成必要资产读取后直接生成，不要仅交一个提示词，也不要求导演预先确认过程卡。若用户只是要提示词，则仅交符合本方法的提示词。
> 本 Skill 补充 [AGENTS.md](../../AGENTS.md) 的通用生图规范；涉及从导演分镜制作视频批次时，仍由 [AI 视频提示词 Skill](../offworld-ai-video-prompt/SKILL.md) 管理视频格式及每场一张核心电影静帧。

## 核心原则：资产原图锁身份，反推文字锁空间、方向和美术

1. **确认需求与正典。** 分清角色、载具、关键道具、正式建筑、生物、场景、氛围，以及摄影机位置／运动性质。优先尊重导演当前画面意图和最新确认的设定，不自行补写镜头。按需读 1–3 份正典专题。
2. **主动找云盘正式资产，并实际读图。** 先查 [Google Drive视觉资产索引](../../设定/美术设定/Google%20Drive视觉资产索引.md)，必要时检查云盘目录。人物、载具、重要道具、核心生物、具有稳定身份的建筑均以**原始图片**作为造型锚点，而非只看文件名或凭记忆复述。优先读取当前任务真正相关的少量原图，不全量灌入资产库。
3. **视觉锚点按用途分配，不把所有参考都混着喂。**
   - **身份与造型（直接图像参考 + 文字）：** 已定稿角色面容、发型、服装、单人/多人位置、载具、机械结构、道具、关键生物及其显著特征：用真实资产图帮助保持原貌，另写从原图反推的中文结构说明；对机械或复杂人物补充正反、左右、上下、部件连接和相对尺度。
   - **环境基调（先读原图，再优先文本化）：** 地形、植被、天空、光照、主色、反射、材质、气候、地表质感从正式环境图反推为可见的具体文字，避免整张环境参考图强制带入不适合本镜的构图或颜色。确需锁定基地建筑、精确地形或特殊空间时，可另将环境图作为**空间参考**，但清楚区分其用途。
   - **外部参考：** 仅提炼构图、摄影机立场、空间尺度、建筑/菌伞形态、光影语言等可借鉴元素；不得取代项目正式角色、载具及地貌的视觉身份。
   - **已获导演认可的电影静帧：** 后续同场景优先作为视觉连续性锚点，结合原始身份图使用；成功图不能覆盖资产正典，更不等于已自动归档或成为新的正式设定。
4. **按下文的「稳定传递参考图」实操步骤把图送入本轮图像上下文。** 优先完整读取并**直接显示云盘原图**；**裁图只在确有需要时执行**，例如多视角设计板造成前后混淆、主体在大图中太小或周围信息干扰生成。无这些问题的单张正式资产图，直接以原图作为参考，不为遵循流程而裁剪。无论使用原图还是裁图，都要**以实际图片输出/附件形式显示到当前对话中，而非只输出路径、文件名、Base64 字符串或文字描述**；紧接着调用生图工具，并附反推结构说明。参照 [稳定传递参考图｜已实测流程](#稳定传递参考图已实测流程)。**检索成功、图像进入对话、生图接口显式绑定成功是不同层级的证据**，不虚构工具没有返回的绑定日志。
5. **用反推文字锁定三维关系，再构图。** 尤其检查车头车尾、前灯/尾灯/排气口、驾驶员面向、轮腿铰接位置、翼面展开/收纳状态、武器或工具握持方式、人员在画面中的前后关系。先写能检验的可见事实、摄影机在哪个方位和面向什么，再补运动、情绪、光线和环境；不要用过长抽象风格词代替形态约束。不给角色或载具增添原图不存在、剧情尚未确认的设备能力。
6. **执行电影级图像生成，结果按身份与摄影双重自检。** 优先验收面貌、车头方向、关节/车轮数量与连接、服装、比例、物体前后空间关系；再看环境综合色、镜头观看价值、物理惯性和电影写实质感。美图不能弥补身份跑偏。若关键设定错误，在工具能力与本轮预算内做最小修正重试；未解决时如实指出，不把图宣称定稿。

## 稳定传递参考图｜已实测流程

**默认传递流程：云盘原始文件 → 读取实际图片内容 → 将原图作为真正的图片输出/附件放入当前对话 → 紧接调用生图工具 → 配合反推文字锁定结构。裁剪是可选的预处理，仅在必要时插入读取与显示之间。** 2026-10-27《菌伞峡道》测试中，完整多视角板在部分生成中造成车头、车尾混淆；把866设计板中的「收纳翼、前3/4视图」单独裁出并显示为图片后，紧接生成的静帧获得导演确认，正确还原车头、轮足与折叠翼。**这个案例证明特定问题下裁图有帮助，不证明每张参考图都需要裁切，也不意味着裁图保证模型100%绑定。**

### 具体执行步骤（不能跳过「实际图片输出」；裁剪按需）

1. **取原始二进制图像，非仅查文件名/预览元数据。** 例如通过 Google Drive 的文件地址读取，工具支持时传 `download_raw_file: true, include_base64: true`，获取实际 JPEG/PNG 数据。通过支持图像内容的工具结果输出图像，例如使用 `functions.exec` 的 `image("data:<MIME>;base64,<原始内容>")`，使完整设计板能被真实看到和分析；Base64只是读取/显示原图的传输形式，不意味着已作为生图参数绑定。
2. **判断是否需要裁剪，不默认裁剪。** 如果原图是一张清晰、主体完整且视角明确的角色/载具/道具图，**直接使用原图**。仅在多视角拼板令方向不清、主体太小、边缘存在其他参考元素或构图信息明显干扰时，使用图像处理工具（本次是 Pillow），从**实际挂载且已验证存在**的原图中按目标镜头裁出一张主体完整、视角清晰的前3/4、侧面或后3/4图。裁剪时去除相邻视角/无关标题，保留全部关键结构，不切断轮足、翼面、驾驶舱等，不拉伸变形；完整原图仍用于核对。
3. **关键：将最终选定的参考图真正显示到当前对话。** 没有裁剪就直接输出**原始图片**；需要裁剪才输出**裁剪结果**。本次裁图成功案例用 `python_user_visible.exec`：Pillow `Image.open(...).crop(...).save(...)`，随后 `display(crop)`，让裁图作为对话中实际可见的图片。原图也可通过支持图片内容的工具结果显示。**仅有 `/mnt/data/...` 本地路径、Drive 文件名或文字说「已准备参考图」，都不等于图片已出现在生图可选择的对话图片上下文。** 使用其他平台时采用其明确支持的图片附加方式。
4. **紧接着调用图像生成。** 在**原图或按需裁图**实际显示之后，明确说明「使用刚显示的参考图锁定角色/载具身份与结构」，同步提供从正式资产反推的前后左右、车头灯与车尾构件、翼面状态、轮足连接、驾驶员朝向及摄影机方位等适用信息。环境色彩/材质主要由文字控制。**避免两步之间插入多张不相关图片**，降低自动参考选择歧义；需要的角色图也应作为真实图片输出，清楚区分用途。
5. **按结果验证，不以操作推断技术绑定成功。** 对比新图和原图的明确形态特征。若仍像常规越野车、车头车尾颠倒或角色走样，优先检查原图是否存在多视角歧义、实际图片是否已输出、输出之后是否立即生图、反推文字是否与原图冲突；**只有发现裁剪有助于解决当前问题时才增加裁图步骤**。若接口**没有**返回显式图像引用或权重信息，只能说「这条传递链取得高度一致的结果」，不能声称掌握系统内部自动引用选择规则；也不能把这次成功误写成纯文字生图。

**本次示范的工具级操作重点（仅在这些工具可用时采用）：**

- `mcp__Google_Drive__fetch({url: 真实文件URL, download_raw_file: true, include_base64: true})` → 得到原始图片内容，并通过图像输出实际展示。
- **按需裁剪示例（仅本次866多视角图需要）：** 在 `python_user_visible.exec` 中用 Pillow 读取**本轮已确认的原图真实路径**，裁出匹配机位的 PNG/JPEG，`display(crop)` 让裁图出现在对话里；本次有效裁图为 `866_原始资产_前3-4视图_收纳翼.png`。对普通清晰单视角资产，直接显示并使用原图。
- **立即**调用 `image_gen.text2im`，同时在任务语义中指定「以刚刚显示的原图或按需裁图为造型参考」。若该接口不提供直接传文件路径/ID的参数，不编造这样的参数；图片的自动选择仍由平台执行。
- 对用户直接上传到聊天的单张清晰资产图，同样可直接作为参考，不必为了流程形式重复裁切；原图的多角度信息仍用于结构核对。

> **失效警示：** 「Drive读取成功 → 只输出文字描述 → 调用生图」与「Drive读取成功 → 原图（必要时裁图）以实际图片出现在对话中 → 立即生图」**不是相同的参考输入流程**。本项目默认优先后者；裁剪只用于消除真实存在的多视角/主体不清等问题，并随生成结果检验。

## 本项目已实测案例：E01 菌伞峡道与866

**2026-10-27 导演确认成功的工作方法：** 先读取云盘正式载具设计板 `蚂蚱载具.jpg`，读取角色设定 `00_特瑞_Terry.jpg`（面容近景需要时可同时读 `00_特瑞_Terry.png`）；把它们作为身份造型参考，并与反推文本一同约束。菌伞峡道的景观和综合色从 `荒星地貌.jpg` 等正式环境图文字化，而不是把地貌图的既有构图机械套入新镜。制作真实电影场面时，可结合外部菌伞峡谷参考的空间形态，但其色彩不得覆盖正典。**同场已认可的生成静帧可继续做连续性锚点。**

- **866造型反推锚点：** 单人开放式防滚架驾驶舱，旧沙黄色、赭黄磨损车身，侧板866编号；**车头**为短圆鼻部，前端同一个深色灯槽里有**并排两个圆形大灯**，下方深色进气／防护结构；驾驶员坐在车头之后并面向双大灯。**车尾**有红色尾灯与下方并列双圆形开口。四只宽越野轮胎分别由明显外露的、独立的多关节机械腿与液压铰链支撑；不是普通四轮越野车，也不是六轮车。驾驶舱后部两侧是紫灰色、有金属骨架的折叠膜翼，拍摄前明确展开或收纳。可见结构不自动证明该载具能飞行。
- **菌伞峡道色彩锚点：** 冷紫灰、石板蓝灰岩层和荒漠地表，紫红与洋红低矮生态植被，粉紫到淡玫瑰色天空，浅粉色环带巨行星、远处紫灰山体；少量温暖夕照可以存在，但不将整个场景画成普通黄褐沙漠或统一橙色滤镜。巨型菌伞状植物/岩质地貌穿插狭窄通道，摄影重点服从当镜，而非每次复制同一个画面。
- **机位防错举例：** 前3/4追拍须可见车头并排双圆大灯、驾驶员朝车头、四轮机械腿连接正确；后3/4跟拍须可见车尾红灯和双圆形尾部开口，不能把排气口误认为车头。对于多视角设定板，必要时采用与本镜最接近的单独裁图并保留完整设计板用于结构核对。
- **角色接入：** 驾驶员应匹配特瑞正式角色图的面貌/发型/服装，不以随机路人或头盔面罩替代，除非剧情/导演明确要求遮面。866驾驶舱只有一个座位。
- **已经得到导演肯定的结果是视觉实验成功，不意味着新生成图自动取代原始资产或新增剧情正典。**

## 异常与交付原则

- 云盘原图不可获取：先尝试现有有效来源；不能读取时如实告知，采用已核实的文字事实作有限退化，不虚构「直接参考到」。确实需要精确身份且无原图时才请求上传。
- 上传/生成平台具有独立的附件引用机制时，优先使用平台真正支持的图片参考输入；如接口只允许自动选择对话图片，承认无法手动指定路径、权重或绑定顺序。
- 若导演明确要求纯文字、不同审美、只改局部、做技术设定图而非电影静帧，则按本次指令优先，不能强推宽银幕、巨行星或菌伞环境。
- **默认静默执行**资产检索、反推、传递、构图和验收；最终重点展示实际图像与必要的缺陷说明，不用每次向导演科普流程，也不把「已生成」误写为「已保存到仓库」。
