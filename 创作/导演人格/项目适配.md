# 导演人格维护｜《异星边境》项目适配

> **配套技能：** [director-persona-maintainer 通用技能](../../skills/director-persona-maintainer/SKILL.md)
>
> **适用范围：** 仅适用于《异星边境 / Offworld Frontier》项目。本文不是第二套 Skill，而是给通用维护技能提供本项目的资料入口、文件职责、协作边界与回归案例。
>
> **当前基线：** 导演代理人格 V3.9（2026-10-30）。版本变化以人格正文与 Git 历史为准。

## 1. 如何与通用 Skill 配合

当任务涉及本项目的导演人格更新、审美校准、长期偏好整理或从创作反馈中修正判断时，**同时读取本文件与通用 Skill**：

1. 先读 [通用维护技能](../../skills/director-persona-maintainer/SKILL.md)，使用其中的证据分级、ADD / UPDATE / DELETE / NOOP、去重和版本维护流程。
2. 再读本文件，取得《异星边境》的项目约束、资料路径和回归测试范围。
3. 按本次任务读取下方对应的人格、审美或方法论文件；完整回顾时还要检查上一版提交以来的相关讨论、Git 修订及被修改的剧本／分镜。
4. 写入只发生在导演明确要求更新、创建或同步时；报告真实改动与真实检查结果，不把未执行的测试写成通过。

**通用 Skill 不应包含本项目的集数、角色、剧情、审美名单或文件路径。** 新项目应建立自己的项目适配文件，并由该项目适配文件指向自己的资料；不要把本文件复制进通用 Skill。

### 资料的上下游边界

- [AGENTS.md](../../AGENTS.md) 是整个仓库的项目协作与创作边界入口，约束所有 Agent；它不替代导演人格。
- [创作方向](../创作方向.md) 负责项目叙事方向与创作原则。
- [设定速查索引](../../设定/速查索引.md)、人物卡、世界设定、美术设定和现行剧本负责事实与正典；导演人格不能创造或覆盖这些事实。
- [编剧 × 导演分镜 Skill](../../skills/offworld-storyboard-director/SKILL.md) 负责剧本、分镜、连续性与制作转译；导演人格维护只负责长期判断，不代写分镜或替代该 Skill。
- [默认生图 Skill](../../skills/offworld-image-generation/SKILL.md) 负责生图与视觉资产流程；本项目审美文件可作为相关视觉偏好的参考，但不取代人物卡、美术设定和正式资产。
- [AI 视频提示词 Skill](../../skills/offworld-ai-video-prompt/SKILL.md) 负责视频生成转译；导演人格不能越过导演分镜擅自补写镜头。

## 3. 本项目的协作约定

- **导演本人主导逐镜分镜。** 默认工作方向是导演先写镜头，AI 按要求反向同步剧本；没有明确要求时，不主动续写未提供的后续镜头或完整分镜。
- **人格是判断参照，不是导演身份或定稿授权。** 代理可以预测、比较、提出反例，但不能自称导演本人，不能替导演确认定稿，也不能凌驾于当前明确指令。
- **最新明确决定优先。** 人格、审美模型和方法论都可能被新反馈修订；旧规则、旧剧本和历史提案不得压过导演当前决定。
- **正典与创作提案分开。** 灵感池、未确认的工作稿、AI 建议和历史版本不能自动升级为事实；沉淀偏好时必须区分导演确认、重复行为归纳和待验证假说。
- **项目事实不进入人格正文。** 角色年龄、人物关系、道具去向、某集事件、镜头细节和制作参数应留在对应正典或制作文件；只有跨情境、可迁移的长期取舍原则才进入人格。
- **不把技术工作拍成技术说明会。** 评估技术流程时，先判断观众需要理解什么、过程本身是否承载期待，以及它带来何种人物行动、风险或可见结果；普通重复步骤优先压缩。
- **不把悬念等同于信息不清。** 观众应能理解已出现的制度、物件、行动和风险；真正未知的原因、链路、记录或后果才留作悬念。
- **不把人物特征过早写死。** 剧本可描述观众需要看见的整体异星差异；具体器官、造型、肤色纹理等由人物卡、美术设定和正式资产负责。
- **不把一切内容都改成戏剧冲突。** 生活、探索、劳动、幽默和视觉发现可以凭自身观看价值成立；不要为追求刺激而强行袭击、反转或制造角色降智。

## 4. 本项目人格更新时的证据等级

- **A｜导演明确表达或明确批准：** 可作为直接证据；仍须保留原本适用范围，不擅自扩大成绝对规则。
- **B｜多个具体选择归纳出的稳定倾向：** 可写入人格或审美模型，但说明这是归纳，保留例外。
- **C｜AI 的解释、预测或尚未得到反馈的提案：** 只能标为待验证假说，不得伪装成导演偏好。

导演沉默、继续讨论或未反对某个提案，不等于确认。AI 事后解释自己“本来就知道导演会选什么”，不算事前预测命中。

## 5. 本项目回归评估案例

人格更新后，按本次涉及的原则选择少量案例回归；不要每次机械测试全部案例，也不要把答案写进题目。案例的用途是检查人格是否能在不同尺度下作出符合导演取舍的判断，不是替代剧本正典。

| 案例 | 应检验的判断能力 |
|---|---|
| E01《异星拾荒》 | 特瑞的荒原老手能力、少年生命力，以及赛车式动态 FPV 与车载 POV 的区分 |
| E02／E13 | 重复出现的居民、群众角色视觉连续性与群像生活感 |
| E02／E15 | 制度与文明信息的可读性；基础信息清楚呈现、真正的未知保留悬念 |
| E03《井口救援》 | 技术救援流程的观看价值判断；压缩无效程序，保留真正承载期待的动作 |
| E07《矿道被封》 | 旧公司地下工程线索与轨道探测器的悬念边界，不擅自解释未知因果 |
| E09《床边看护》 | 熟人照护与专业治疗的不同价值，人物通过行动建立关系 |
| E10《意外断电》 | 生产改善必须落到可见生活结果，而不止设备短暂亮灯 |
| E13《一箱土豆》 | 生活戏、视觉趣味、人物关系和群像交叉的独立观看价值 |
| E18《荒星光点》 | 主角真正拥有离开的自由后，主动折返所形成的情感选择 |

具体剧情细节始终以当前剧本和正典为准；表格只保留测试主题。若集数、剧情或分集名称变化，应同步更新本表，但不把旧编号写入通用 Skill。

## 6. 本项目文件维护约定

- 导演代理人格正文建议保持约 6,000–10,000 字符，原则上不超过 12,000 字符；超限先合并、去重、压缩案例，不以拆分平行人格文件规避。
- 审美文件优先维护跨作品判断维度与少量代表证据，不按每部作品建立冗长影评。
- 方法论文件只沉淀可复用的诊断、改造和验证方式；单集事实与新剧情不进入其中。
- 版本号只维护在对应正文，不在多个入口复制一份可漂移的版本记录；本适配文件的“当前基线”只作导航，更新后同步修改。
- Git 历史负责详细变更记录；正文不维护按日期堆积的修改流水账。
